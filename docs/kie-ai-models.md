## 3. Методика: что откуда взято

- **Живой API kie.ai — первоисточник для id модели, бренда, типа задачи и цены.** `/api/v1/models` отдаёт `model` (id), `provider`, `taskType`, `description`, `pricingDesc` (официальный текст цены: кредиты и USD, за что именно — за секунду / картинку / ролик, с разбивкой по разрешению и звуку).
- **docs.kie.ai — первоисточник для настроек.** На каждой странице модели лежит OpenAPI-спека `POST /api/v1/jobs/createTask` со схемой `input`: имена полей, типы, enum-значения, дефолты, min/max, обязательность. Схемы скачаны машинно (308 страниц) и распарсены; ничего не додумано вручную.
- **`app/services/kie_catalog.py` — первоисточник для 22 моделей каталога, которые студия реально вызывает** (это 27 строк отчёта: у части моделей два id — t2i и i2i). Для них в колонке «Настройки» стоят поля каталога (то, что уходит в payload), а в разделе 6 — правила цены из кода и ограничения из `build_payload`/`validate_values`.
- `web/src/lib/kie-pricing.ts` — зеркало расчёта цены на фронте: `цена = unit_credits × multiplier`, где для `unit=sec` множитель — `duration`, для `1k_chars` — число тысяч символов. Использовано для проверки, что цена в коде считается за секунду/за генерацию, а не иначе.
- `app/bots/kie_http.py` — что реально шлёт клиент: `POST /api/v1/jobs/createTask`, `POST /api/v1/veo/generate`, `POST /api/v1/generate*` (Suno), `GET /api/v1/chat/credit`, заголовок `Authorization: Bearer <key>`.

Обозначения: `обяз.` — обязательное поле; `деф. X` — дефолт; `значения: a|b|c` — enum; `файл/URL` — нужна ссылка на файл; `⇄цена` — поле входит в правила цены каталога студии; «неизвестно» — данных в источниках нет.

В таблицах цена приведена без маркетинговых хвостов про бонусы топ-апов («High-tier top-ups …») — это не цена шага. Полный дословный прайс лежит в CSV, колонка «прайс как в kie.ai».

## 6. Модели каталога студии (`kie_catalog.py`) — подробно

Настройки — из кода (это ровно то, что уходит в payload). Цена — из правил `pricing` каталога; сверка с живым прайсом — в разделе 7.

Важно: у моделей с `model_map_i2i` (flux-2-pro, seedream-5-pro, gpt-image-2, qwen3-image, kling-2-6) один спек полей на два id — t2i и i2i. В строке t2i-варианта поле `image_urls` тоже видно; при наличии картинки код подменяет `model` на i2i-вариант. Поэтому «лишнее» поле в строке t2i — это не ошибка отчёта, а устройство каталога.

### 7.2 Настройки (имена полей, эндпоинты)

- **Veo 3.1 — другой транспорт.** Код ходит на старый `POST /api/v1/veo/generate` с полями `generationType`, `enableTranslation`, `imageUrls` (camelCase), режимы `veo3_lite|veo3_fast|veo3`, дефолт `veo3_lite`. Доки для `veo-3-1` описывают `POST /api/v1/jobs/createTask`, внутри `input` — `generation_type`, `enable_translation`, `image_urls` (snake_case), `model` с дефолтом `veo3_fast`. То есть код сидит на старой ветке API.
- **`gpt-image-2-image-to-image`: имя поля референсов не совпадает.** Код шлёт `image_urls`, дока требует `input_urls` (≤16). Автопереименование в `kie_http.py` есть только для flux (`i2i_input_field`), у gpt-image-2 его нет → референсы могут не уходить. Платной проверкой не подтверждал.
- **`nano-banana-2-lite`: имя поля референсов.** Код шлёт `image_input`, дока ждёт `image_urls` (≤10). У `nano-banana-2` в доке действительно `image_input` — похоже, lite живёт по другой схеме. Тоже кандидат на тихий отказ референсов.
- **`kling-3.0/motion-control`: другие имена.** Код шлёт `image_urls` + `resolution`; дока ждёт `input_urls` (картинка), `video_urls`, `mode` (720p|1080p) и `character_orientation` (video|image).
- **`qwen3/*`: не те поля.** Код шлёт `aspect_ratio`; в доке вместо него `image_size` (default 16:9) + `resolution` (1K|2K) + `output_format`, `prompt_extend`, `negative_prompt`, `seed`, `nsfw_checker`. Т.е. пропорции из UI, скорее всего, не доезжают (`aspect_ratio` в схеме отсутствует).
- **`hailuo/2-3-image-to-video-pro`: лишнее поле.** Код шлёт `mode=standard|pro`, но в доке тир выбирается id модели (`...-pro`/`...-standard`), а поля `mode` в схеме нет. Дефолт кода `mode=standard` при модели `-pro` — расхождение.
- **`kling-3.0/video`:** у кода нет полей `multi_prompt` и `kling_elements` (есть в доке); `sound`, `duration`, `mode`, `multi_shots`, `image_urls`, `aspect_ratio` — совпадают.
- **`bytedance/seedance-2-5`:** в доке есть `omni_reference_task_type` (auto|reference|edit|extend), `output_format` (mp4|mov), `web_search`, `draft`, `nsfw_checker` — в каталоге студии их нет.
- **`bytedance/seedance-2-fast`:** в доке есть `web_search`, `return_last_frame` — в коде нет. **`seedance-2-mini`:** в доке есть `reference_audio_urls` — в коде нет. **`seedance-2`:** в доке есть `nsfw_checker` — в коде нет.
- **`kling-2.6/image-to-video`:** код передаёт `aspect_ratio` только для t2v (при фото убирает) — в доке `aspect_ratio` в схеме i2v вообще нет, т.е. поведение совпадает с докой за счёт костыля в `build_payload`.
- **`nano-banana-2`:** код дефолт `output_format=png`, в доке дефолт `jpg`; в доке `aspect_ratio` шире (`1:4|4:1|1:8|8:1`, дефолт `auto`).
- **`seedream/5-pro-*`, `wan/2-7-*`, `seedance-2*`, `qwen3/*`, `flux-2/*`, `gpt-image-2/*`:** в доках есть `nsfw_checker` — в каталоге студии его нет ни у одной модели.
- **Метаданные kie.ai:** модель `ideogram/v3-text-to-image` в `/api/v1/models` помечена как `Text to Video`, хотя id и прайс — про картинку. Похоже на ошибку в `taskType` на стороне kie.ai; в этом отчёте она попала в раздел «Видео» так, как её отдаёт API.

3. **Нет страницы в доках** у 36 моделей. Из них у 6 настройки всё равно известны — взяты из кода студии: `topaz/image-upscale`, `kling-2.6/text-to-video`, `kling-3.0-omni/text-to-video`, `kling/v3-turbo-image-to-video`, `kling/v3-turbo-text-to-video`, `wan/2-7-image-to-video`.
4. **Связи «параметр → множитель цены» в доках kie.ai нет.** Для моделей не из каталога студии влияние на цену восстановлено только по тексту прайса (упоминания разрешения/секунд/звука) и помечено «Влияет на цену (по тексту прайса)»; это эвристика по тексту, а не гарантия. Для остальных — не указано.
5. **Фактических списаний нет:** платных генераций не запускал, поэтому цены — из прайса kie.ai, а не из истории списаний по конкретной генерации.
6. **Скрытые лимиты** (rate limit, максимум файлов, размеры) есть только там, где они описаны в схеме доков; глобальные квоты аккаунта не проверялись.
7. **Две страницы доков не скачались с первого раза** (`wan/3-0-video`, `wan/3-0-video-prime` — сервер закрывал соединение); повторный запрос их отдал, схемы включены в отчёт.
