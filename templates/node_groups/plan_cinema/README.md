# Группа `plan_cinema` — «Кино по плану»

Ролик строится из **плана** (`project.general_plan`), а не из закадрового текста: сцены → персонажи →
диалоги → каркас → кадры → фоны → QC → стиль → отчёт. В обычном режиме закадра в этой цепочке нет:
`Frame.voiceover_text = ""`, поля `закадр` нет ни в сцене, ни в кадрах, VO-гейты отключены (`vo_mode=False`).
Если к «Шотам» подведено ребро от ноды «Закадровый текст», шаг «Шоты» идёт в **режиме VO** и раскладывает
весь закадр по кадрам — см. §«Режим VO: закадр подведён к Шотам».

Цепочка (все рёбра `after`, `project_meta={"source_mode": "plan"}`):

**Сцены по плану → Персонажи → Каркас → Диалоги → Шоты → Фоны → QC → Стиль → Отчёт → Правки кадров**

Порядок «Фоны» после «Шотов» — намеренно: шоты пишут кадры, фоны читают **кадры** (`Frame.attrs["кадры"]`), объединяют их по локациям и заводят `f0N` только для повторяющихся мест. Одиночное место карточки не получает: кадр опирается на `место` сцены, а `фон` сцены остаётся пустым.

Врезки и статисты: сцена с `сцена_вставка: true` — отдельная короткая сцена на 1–2 кадра со своим местом; следующая за ней сцена с `возврат_к_сцене: N` продолжает сцену N на прежнем месте и прежнем фоне (`продолжение_фона: true`), новый фон не заводится. Люди, которые во всех кадрах локации стоят на одном месте, — статисты: их рисуют сразу на фоне (поля карточки `статисты` и `перемещения`, «кто, откуда, куда»); герои `c0N` на фон не попадают.

Как «Фоны» собирают карточки (`templates/node_groups/plan_cinema/plan_backgrounds.md`):

1. Кадры одной сцены с одной локацией — один фон; вставка (другая сцена в другом месте) — свой фон.
2. Продолжение сцены после вставки берёт прежний код: второй `Entity` не создаётся.
3. Карточка заводится, только если локация встречается в кадрах больше одного раза; одиночное место описывается в промте кадра.
4. Время суток — часть локации: одно место днём и ночью — два фона.

Код проверяет форму ответа (`id` `f0N`, `сцены` из входа, каждый номер не больше чем в одном фоне, порог повторяемости), пишет `Entity(type="background")`, `attrs["фон"]` сцены и `фон_код` каждому её кадру, затем гейт `R-BG-REF` проверяет непустые коды. Если кадров ещё нет — шаг падает с «сначала „Шоты“»; если `frame_uuid` только в `shots.json` (не доехал до БД), кадры берутся из артефакта.

Стиль можно задать двумя способами: выбрать файл из папки стилей или загрузить свой текст в «свой промт» ноды — тогда в поле стоит имя загруженного файла, а текст берётся из библиотеки промтов. Жёсткое требование «файл должен называться `style_*.md`» снято: оно ломало второй способ.

Нода «Фоны» **рисует** локации тем же стилем: промт фона = карточка (`промт` → `описание` → `свет`) + STYLE-блок выбранного варианта ноды «Стиль». Своего списка стилей у фонов нет; своя привязка (слот `style` на ноде `n_backgrounds`, как у «Персонажей») перебивает наследование и снимается пустым значением. Итоговый промт каждой карточки видно без генерации: `GET /api/projects/{id}/backgrounds/{code}/prompt`, варианты стиля — `GET /api/projects/{id}/backgrounds/styles`, привязка — `POST /api/projects/{id}/backgrounds/style {"variant": "style_…" | ""}`.

| Персонажи | план + сцены | `Entity(type="character", code="c01"…)` с `имя/внешность/одежда/характер/правила/voice_prompt/voice_id` | `R-CAST-DUP` |

| Диалоги | сцена + реестр | `Frame.attrs["речь"]` = `{тип, реплики:[{кто, текст, эмоция}]}` | `R-DLG-FORM`, `R-DLG-SPEAKER` |
| Шоты | сцена + `речь` + `место`; в режиме VO + полный закадр с ребра от ноды «Закадровый текст» | apply-ops `{"frame_uuid": "<uuid сцены>", "fields": {"кадры": [...]}}`; в режиме VO у кадра есть `закадр`, у сцены — `voiceover_text` и `duration_seconds` | `R-DLG-SHOT`; в режиме VO код дополнительно сверяет покрытие закадра и темп 13.5 |

| Стиль | выбранный `style_*.md` + кадры сцен | `промт_картинки` K1 = сцена + стиль, `промт_без_стиля`, `стиль`; `frames.image_prompt` | `R-STYLE-LEN` |

Гейты покрытия считаются кодом, не моделью: `app/services/plan_scenes.py`
(`num_plan_points`, `parse_scenes_reply`, `check_plan_coverage`). При провале — один повтор,
затем `gate_status=fail` и цепочка стоит.

## Режим VO: закадр подведён к Шотам

Правило владельца: если к ноде «Шоты» подведено ребро от ноды «Закадровый текст» (`type=script`),
нода **обязана** использовать весь закадр. Тогда шаг «Шоты» идёт в режиме VO. Без ребра ветка
прежняя: кадры без закадра, `voiceover_text = ""`.

Что делает режим:

1. **Закадр берётся с ребра.** Полный текст ролика — `db_v2.resolve_full_voiceover_text(project)`
   (`project.script_text`, иначе `voiceover.txt`). Пустой текст — ошибка шага, молча работать
   без закадра нельзя.
2. **Деление по сценам** — внутренний промт `plan_vo_partition.md` (на канвасе не выбирается):
   каждой сцене свой непрерывный кусок, куски идут по возрастанию номера, каждый непустой, склейка
   кусков = весь закадр слово в слово. Сверяет код; при расхождении — 2 попытки с блоком «Исправь»,
   затем шаг падает с перечнем конкретных проблем (молчаливое смещение сцен запрещено).
3. **Раскладка по кадрам** — промт `scenes_to_frames_plan_vo.md`: у каждого шота в `кадры[]`
   появляется поле `закадр` — дословный непрерывный кусок куска сцены, куски идут по порядку,
   склейка = кусок сцены. Если модель вернула куски не по тексту, код раскладывает кусок сцены
   детерминированно по числу шотов (`camera_expand.split_text_into_parts`) — текст не теряется.
4. **Темп 13.5 знака в секунду.** Длительность кадра = число знаков его `закадр` / 13.5; сумму
   по ролику считает **код**, не модель. Поэтому число кадров диктует текст: ориентир 30–80 знаков
   на кадр (2,2–6 с), до 120 знаков (≈9 с) — исключение для длинной фразы. Жёсткого максимума
   кадров нет: их столько, сколько нужно, чтобы разложить весь кусок сцены, — на сцену в ~900
   знаков уходит ~9–12 кадров. Микро-фразы и кадры на полминуты — брак.
5. **Сцена.** `Frame.voiceover_text` = её кусок закадра, `Frame.duration_seconds` = сумма
   длительностей её шотов.
6. **Артефакт.** `shots.json` получает `закадр_план` (куски по сценам) и `темп` (13.5).

Кадр в режиме VO обязан иллюстрировать свой кусок: место, кто в кадре и действие соответствуют
смыслу звучащего текста, смена точки действия в тексте — смена кадра и плана. Реплики `речь`
раскладываются как раньше (`говорит`, `реплика`) и не теряются; кадр с репликой тоже получает
свой кусок закадра — диктор и персонаж живут в одном кадре.

Проверка после прогона: в `reports/shots-report.html` у кадров видно `закадр`, у сцен — свой кусок;
сумма длительностей сходится с `длина закадра / 13.5`. Перезапуск «Шотов» по сцене чинит только
эту сцену; сам закадр правится в ноде «Закадровый текст», а не в кадрах.

## Чем отличается от `script_frames_qc`

1. Вход — план, а не закадр: нет ноды «Границы» (режет план «Сцены по плану»), нет склейки VO.
   Закадр входит только в режиме VO — одним ребром от ноды «Закадровый текст» (§«Режим VO»).
2. В обычном режиме `voiceover_text = ""` у всех сцен, поля `закадр` нет в схеме кадра, VO-правила
   (26–80 / 12–30, дословность, покрытие VO) не применяются, валидаторы вызываются с `vo_mode=False`.
   В режиме VO закадр раскладывается по сценам и кадрам по правилу 13.5 знака в секунду (куски
   30–80 знаков), а не по старым окнам 26–80 / 12–30.
3. Речь — отдельная сущность сцены (`attrs["речь"]`), а не VO: диалоги пишутся до шотов, шоты
   раскладывают реплики по кадрам (`говорит`, `реплика`), код проверяет их через `shots_dialogue_problems`.
4. Персонажи — отдельный шаг «Персонажи» (реестр `Entity(character)`), есть гейт дублей `R-CAST-DUP`;
   в старой группе реестр собирался внутри «Каркаса».
5. Фоны — отдельная сущность на локацию: нода «Фоны» после «Шотов», у сцены `attrs["фон"]`, гейт `R-BG-REF`.
6. Сцена — ячейка `Frame` с `attrs["источник"] == "pk"`; по этому ключу отличаем сцены новой цепочки от старых.
7. «Стиль» и «Отчёт» переиспользуют логику старой группы; промты и id нод новые, `pk_*`.

Ставится с `default_after_type="plan"`; вместе с `script_frames_qc` не ставится
(`mixed_group_conflict_error`). Старые проекты без `meta.source_mode == "plan"` не меняются.

## Если гейт упал

| гейт | что значит | что делать |
|---|---|---|
| `R-PLAN-COVER` | план не покрыт сценами, ссылки убывают или есть `P` вне плана | прочитать в отчёте `uncovered` / `unknown` / `errors`, перезапустить «Сцены по плану» (один автоповтор уже был); кривой план чинить в «Сценарии», а не в нодах |
| `R-CAST-DUP` | два персонажа с одним именем после нормализации | перезапустить «Персонажи»; имя основы свести к одному `cNN` |
| `R-DLG-FORM` / `R-DLG-SPEAKER` | форма `речь` не по контракту или `кто` вне реестра/сцены | перезапустить «Диалоги» по этой сцене, править `речь` в `attrs`, а не кадры |
| `R-DLG-SHOT` | реплики не разложены по кадрам | перезапустить «Шоты» по сцене; реплика дословно из `речь` |
| `R-BG-REF` | у сцены нет фона или фон не существует | перезапустить «Фоны»; проверить `attrs["фон"]` сцены против `Entity(background)` |
| `R-STYLE-LEN` | стиль не влезает в лимит 4877 | взять другой файл стиля; стиль не режется никогда |
| `qc.verdict == fail` | семантические нарушения от GPT-QC | смотреть `violations` и `fixes`, повторять «Шоты» / «Диалоги» по указанным кадрам |

В режиме VO ошибка покрытия закадра или раскладки `закадр` — это падение шага с перечнем проблем
в логе, а не «мягкий» пропуск: шаг не пишет кадры, пока текст не разложен целиком.

Проверка после прогона: `reports/shots-report.html` (сцены, кадры, речь, фоны) и
`excel_gpt_uploads/n_excel_gpt_pk_style/style_report.json`.
