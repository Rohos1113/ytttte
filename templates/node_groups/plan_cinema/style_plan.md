# Нода «Стиль» группы «Кино по плану»

Спецификация поведения кода. **GPT не вызывается.** Нода берёт выбранный файл стиля и дописывает его
после промта главного кадра каждой сцены, затем пишет тот же текст в `frames.image_prompt`.

Нода: `pk_style` · id `n_excel_gpt_pk_style` · `outputMode=artifact` · `transport=code`.
Промт-вариант (`style_noir_watercolour_16_09` и т.п.) — это **имя файла стиля**, а не текст промта.

Механика ноды переиспользуется из `app/services/frame_style.py` (копировать её в новый модуль не нужно):
там `STYLE_GROUP_ID = "script_frames_qc"`, то есть файлы стилей читаются из общей папки
`templates/node_groups/script_frames_qc/styles/style_*.md`. Копий стилей в `plan_cinema` нет: новая
группа берёт те же `style_noir_watercolour_16_09`, `style_archival_noir_watercolor_aug`,
`style_knitted_textile`. Если при реализации для `plan_cinema` заведут свою папку `styles/`, формат
файла не меняется — понадобится только параметр каталога в загрузчике стиля.

---

## 1. Вход

| вход | что это | откуда |
|---|---|---|
| вариант промта ноды | имя стиля `style_*` или пусто/`default` | выбор в Studio, `read_resolved_project_prompt(..., node_key)` |
| стиль-файл | `style_*.md`, минимум одна строка `STYLE: …` | `templates/node_groups/script_frames_qc/styles/` (общая папка, `frame_style.STYLE_GROUP_ID`) |
| сцены | `Frame` с непустым `attrs["источник"] == "pk"` и непустым `attrs["кадры"]` | БД проекта |
| сцены старой цепочки | `Frame` без `источник == "pk"` | БД проекта, **не обрабатываются** |

Пустой вариант или `default` → берётся стиль по умолчанию `style_noir_watercolour_16_09` с записью в лог.
Выбран файл, которого нет → `StyleError`, прогон стоит.

## 2. Что считается сценой в режиме plan

Ячейка `Frame` (папка `Scene` — организационная, не сцена). Сцена годится, если:

1. `attrs["источник"] == "pk"` (ровно этот ключ и значение, опечатка = не наша сцена);
2. `attrs["кадры"]` — непустой список объектов.

Строки без `источник == "pk"` пропускаются и считаются `skipped_foreign_rows`. Это защита: старая
цепочка в проекте со `source_mode == "plan"` не должна получить наш стиль.

Главный кадр сцены (**K1**) — первый «живой» кадр с `parent_id` пустым/`null`, предпочтительно с непустым `id`;
иначе первый живой кадр; иначе первый объект списка. Остальные кадры — дети (K2…): их `промт_старт` и
`промт_конец` тоже получают стиль, но по правилам §4.

## 3. Порядок действий

1. Разрешить стиль: вариант → имя → файл → текст (`normalize_style_text`: CRLF → LF, схлопнуть пустые
   строки, `strip()`). Пустой текст = `StyleError`.
2. Посчитать бюджет: `limit = OUTSEE_PROMPT_TARGET_BODY_CHARS = 4877`,
   `block_cap = min(700, limit - MIN_SCENE_BUDGET)`, `MIN_SCENE_BUDGET = 200`.
   Длиннее `block_cap` → `StyleError` (`R-STYLE-LEN`). Стиль режется **никогда**.
3. Отобрать сцены (§2), отсортировать по `sort_key`, `number`, как и раньше.
4. Для каждой сцены найти K1 и взять текст сцены **без стиля** в порядке приоритета:
   `промт_без_стиля` → `промт_картинки` → `промт_старт` → `раскладка` → `действие`.
   Из взятого текста срезать хвост `STYLE` / `Final style lock` / `Negative` (`strip_style`).
5. `budget = limit - len(style) - 2` (разделитель — `"\n\n"`). Меньше `MIN_SCENE_BUDGET` → `StyleError`.
6. Сжать сцену до `budget` **по границе предложения**: последняя точка `.!?…;` (за ней пробел или конец)
   в пределах `budget`, но не раньше половины бюджета. Нет подходящей границы — резать по последнему
   пробелу. После обрезки снять хвостовую пунктуацию `,;:—-` и перевод строки.
7. Собрать: `final = сцена + "\n\n" + стиль`. Пустая сцена после обрезки → только стиль.
8. Записать в кадр K1:
   - поле откуда взята сцена (`промт_картинки` или `промт_старт`) = `final`;
   - `промт_без_стиля` = сцена до обрезки (источник для повторного прогона);
   - `стиль` = имя варианта;
   - `стиль_поле` = имя поля, куда записан стиль.
9. Детям (`промт_старт`, `промт_конец`) — та же процедура §5–7, исходники в
   `промт_старт_без_стиля` / `промт_конец_без_стиля`. Пустых промтов у ребёнка не придумывать:
   нет текста — счётчик `children_no_prompt`.
10. `fr.attrs` — новая копия (не мутировать на месте), `flag_modified(fr, "attrs")`.
    `frames.image_prompt` = тот же `final` только у строки сцены; у ребёнка — своё поле, `image_prompt` строки не перезаписывать.
11. Статус: `planned` → `image_prompt_ready` (только если статус был `planned`).
12. Записать отчёт `excel_gpt_uploads/n_excel_gpt_pk_style/style_report.json` (+ копия в
    `node_trace/pk_style/<ts>/`), `meta["frame_style_report_path"]`, отметить слот завершённым.

    "source_раскладка": 0

  "styled": [
    {"number": 1, "uuid": "<uuid сцены>", "k1": "1-S1-K1", "field": "промт_картинки",

`no_prompt` — строки, где у K1 нечего взять (`k1: null` — не нашли главный кадр).

## 5. Идемпотентность

Повторный прогон и смена стиля не дублируют хвост: сцена всегда берётся из `промт_*_без_стиля`
(иначе из поля после `strip_style`). Второй прогон с тем же стилем даёт `unchanged` и одинаковый
`final`, инвариант `len(final) <= 4877` держится всегда.

## 6. Ошибки и что делать

| ситуация | результат | что делать |
|---|---|---|
| стиль-файл не найден / пустой | `StyleError`, нода стоит | выбрать существующий `style_*.md` в Studio |
| стиль длиннее `block_cap` | `StyleError` (`R-STYLE-LEN`) | взять другой файл стиля; стиль не режем |
| у сцены нет главного кадра | строка в `no_prompt`, остальные сцены обрабатываются | прогнать «Шоты» для этой сцены |
| у сцены пустой `кадры` | не считается сценой | дозаполнить «Шоты» |
| сцена старой цепочки рядом | `skipped_foreign_rows` | норма: она не наша |

## 7. Что нода НЕ делает

- Не вызывает GPT и не придумывает стиль.
- Не трогает `промт_картинки` детей, кроме `промт_старт`/`промт_конец` (§3.9).
- Не пишет реплики, `фон`, `фон_код`, `attrs["речь"]`, не трогает `voiceover_text` сцены (остаётся `""`).
- Не меняет `план`, `ракурс`, `высоту`, `объект`, `parent_id`, порядок и число кадров.
